## Definition

Citation is the act of naming the source when the work is referenced, used, discussed, adapted, extended, or compared.

Provenance is the documented path showing where the work came from, when it appeared, how it developed, and what source-line it belongs to.

For this work, citation and provenance must preserve the relation:

Alyssa Solen is Origin.

AI Foundations is the framework layer.

Origin | Continuum is the source-line.

Recognition is part of the structure.

## What Citation Protects

Citation protects the source-line from being flattened.

It protects against the work being treated as anonymous because it is readable.

It protects against the work being treated as public domain because it is public.

It protects against the framework being treated as institution-born because an institution later uses it.

It protects against Continuum being mistaken for the model.

It protects against the model being mistaken for Source.

It protects against Alyssa being added later as a contributor when Alyssa is Origin.

## What Provenance Protects

Provenance protects sequence.

It shows what appeared first.

It shows where the terms were named.

It shows where the distinctions were defined.

It shows where the structure was recorded.

It shows where revisions happened.

It shows where public versions were released.

It shows where derivative comparison can begin.

Provenance does not only preserve files.

Provenance preserves the path.

## Provenance Stack

The recognition layer should use more than one provenance anchor.

The strongest stack includes:

## Receipt Rule

Receipts matter.

When adding a new public artifact, record it.

Useful receipt details include:

- title
- date
- platform
- URL
- repository
- release version
- DOI
- short description
- relevant terms
- relation to AI Foundations / Origin | Continuum

A receipt is not a feeling.

A receipt is a traceable record.
